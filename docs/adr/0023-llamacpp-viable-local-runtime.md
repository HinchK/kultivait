# llama.cpp viable as local runtime (conditional GO)

Following map #202 (tickets #205, #208, #209), kultivait records a **conditional GO** verdict on llama.cpp: llama.cpp is viable as the local runtime on Apple Silicon, but switching the default runtime from Ollama (ADR 0006) is strictly gated on resolving kultivait-side wiring and tool-translation defects (C1 and C2). This decision meets the architectural significance test: reversing a runtime pivot after migration is hard in practice once configs, process managers, and model caches align around it; operating llama.cpp introduces real architectural trade-offs (router-mode process supervision, single-port chat plus embeddings, and exclusive execution under the never-both-up constraint vs. Ollama's daemon model); and declaring a GO verdict despite initial gate failures is surprising without the root-cause context. Rigorous evaluation under ADR 0015 and ADR 0017 discipline demonstrates that the runtime itself is stable and faster, with all observed failures stemming from kultivait product and harness bugs. **EVIDENCE**: #205 embeddings gate PASS 6/6, p50 11 ms / p95 13 ms against 500/1500 ms bars. #208 paired serving on the 17 text dispatches the kultivait preprocessor bug did not touch: llama.cpp 15/17 vs ollama 14/17; on the 14 rows both completed, first-token p50 = 0.92x ollama (19.5 s vs 21.2 s), faster on 9/14; ReadTimeouts 2 vs 4; zero llama-server crashes under concurrent live herd load. Every llama.cpp-leg failure was kultivait's: 8x HTTP 500 = #211 (preprocessor generator hardwired to localhost:11434/ollama because cmd_serve passes no preprocess_generate, cli.py:632, server.py:96-99,155; run_preprocessor catches only TimeoutError so ConnectError becomes ASGI 500); the /v1/messages tool-schema bug (research/claude-socket-loopback 67e5999, backends.py:138,250) hits both local backends. **CAVEATS**: (1) p95 <= 15 s FAILED on both runtimes (ollama 89 s, llama.cpp 40 s) — bar-calibration finding, not a runtime verdict; (2) the tool-bearing gate (#204 gate 2) is UNANSWERED — harness R12 excluded tool rows on both legs; (3) locked set had 20/30 unique prompts; preprocessor path not exercised cleanly; (4) live :4114 stack logged 8 preprocessor ASGI crashes; contested prompts 500 until C1 lands. **CONDITIONS**: C1 (blocks switch) = fix #211 wiring: pass preprocess_generate from active config in cmd_serve + shadow/eval call sites (cli.py:1318,1388), widen run_preprocessor error handling per its docstring, add a test that a llamacpp config yields a :8080 generator. C2 (blocks switch) = translate Anthropic tools to OpenAI at the local-backend boundary (reuse api_backends.py:71-86) with live regression tests. C3 (evidence debt, not a blocker) = clean tool-bearing serving gate scoring tool_calls deltas + recalibrated long-prompt-aware latency bar, optionally one clean paired re-run with herd traffic paused. GO does NOT flip the default runtime.

## Considered Options

- **Immediate default switch** (flipping `runtime = "llamacpp"` as product default now): rejected — C1 (contested prompt ASGI 500s due to hardwired Ollama preprocessor generator) and C2 (Anthropic tool-call incompatibility at local backend) are critical path blockers that break live agent loops.
- **NO-GO** (20/30 unique + unanswered tool gate too thin): rejected: paired evidence favors llama.cpp, all failures kultivait's.
- **Defer for clean re-run**: rejected: directional numbers already in hand, re-run costs a session.

## Consequences

- Ollama remains the default runtime; `runtime = "ollama"` continues as default in configuration templates until C1 and C2 land.
- Follow-on map owns resolving condition C1: fix #211 wiring by passing `preprocess_generate` from active config in `cmd_serve` + shadow/eval call sites (`cli.py:1318,1388`), widen `run_preprocessor` error handling per its docstring, and add a test that a llamacpp config yields a `:8080` generator.
- Follow-on map owns resolving condition C2: translate Anthropic tools to OpenAI at the local-backend boundary (reuse `api_backends.py:71-86`) with live regression tests.
- Follow-on map owns condition C3 as accepted evidence debt: clean tool-bearing serving gate scoring `tool_calls` deltas + recalibrated long-prompt-aware latency bar, optionally one clean paired re-run with herd traffic paused.
- Follow-on map owns the graduated fog: default-runtime policy under never-both-up, ollama coexistence, distillate GGUF serving when a distillate exists.
- ADR 0015 discipline continues for re-pinned bars.
