# API retry & failover: aggressive buffered retry, fail-fast headless, unbounded failover for human toll picks

API dispatches retry **aggressively on the same target** — up to 5 attempts, exponential backoff with jitter (1s base, jittered), honoring provider headers exactly when present (Anthropic `retry-after`, OpenAI `Retry-After`, OpenRouter 429 `X-RateLimit-Reset`), with a total added-latency budget (~120s) rather than a per-wait cap; non-retryable 4xx (auth, validation) fail fast — a bad key surfaces immediately, never hammered. Aggression is made safe by **buffered relay**: the proxy buffers the provider's stream fully before relaying to the client (client-facing SSE is emitted from the buffer, preserving the client's streaming interface), so a provider failure at any generation point is a **pre-stream failure** — the mid-stream partial-content problem is dissolved by construction, failed attempts are discarded and retried whole, and buffer size is bounded by the per-model token table (docs/adr/0008-api-effort-projection.md). The conscious price: time-to-first-token at the proxy hop grows to full generation time — map #25's streaming-fidelity note is revised here; token-by-token arrival is traded for clean failure semantics and transparent retries. When retries exhaust (or a non-retryable error hits), the outcome is **presence-gated**: auto-policy and headless dispatches **fail fast** with a dialect-native error response (chat-completions: HTTP error status with JSON body, or error-terminated SSE; messages: Anthropic's `event: error` shape) — no cross-target failover, no local-tier dump, the client's agent loop owns recovery (docs/adr/0002-orchestration-fit-at-boundaries.md); a **human toll pick** instead fails over **unbounded**: the dispatch walks the entire registered-and-capable candidate ranking — past the menu's top three, off-menu targets included, keep-it-local included — until one serves, bounded only by the capability filter (docs/adr/0006-mixed-route-menu.md: never onto a target that cannot execute the request as sent; #29's fail-fast survives). A present human answered a toll; the proxy finishes the job rather than paging them again. Every hop is recorded: the ledger keeps `route_choice` (the human's pick), the serving target, a `fallback_reason: "provider_error:<target>"` chain, and retry telemetry (attempts, backoff total, failure class); failure details never leak key material (docs/adr/0010).

## Considered Options

- **Bounded retry (≤2, ~30s cap)**: rejected — the herd chose availability over added-latency conservatism for proxy dispatches; aggressive retry with jitter is safe under buffered relay because failed attempts never reach the client.
- **Dialect-native mid-stream error frames** (terminate SSE with `error`, partial content stands): rejected — superseded by buffered relay, which makes mid-stream failures structurally impossible at the client boundary; the dialect-native error survives only as the pre-stream failure response.
- **Pre-stream one-hop ranked failover for all dispatches**: rejected as a universal rule — headless dispatches fail fast so the client's agent loop stays the orchestrator; failover is reserved for answered tolls where a human delegated completion.
- **Human picks never fail over** (error out, let the present human re-choose): rejected — converts presence into a pager; the toll answer IS the delegation.
- **Full-buffer relay vs passthrough streaming**: accepted cost — TTFT at the proxy hop grows to full generation time; recorded as a revision of map #25's streaming-fidelity note, revisitable if TTFT proves painful in dogfooding.

## Consequences

- Client-visible behavior: streaming responses arrive as a burst after provider completion; every failure is a clean, complete error — never truncated content, never an ambiguous EOF.
- Retry and buffer state is per-dispatch and ephemeral; the ledger is the durable record (attempts, hops, failure class, serving target).
- OpenRouter's internal provider fallback composes: its 429 arrives already self-exhausted and enters the same aggressive-retry rule.
- The presence probe (docs/adr/0010) still governs menu candidacy; this policy governs dispatch, not menus.
- Tollbooth mechanics are untouched: late-answer counterfactuals, stickiness, and auto-policy resolution behave exactly as before; only the post-answer dispatch path changes.
- Term canonized in CONTEXT.md: **Buffered relay**.
