# The design-partner consent and egress posture: pull-only, metadata-default, ask-once egress

Following Map #221 and the ratified design-partner protocol pin (#222), kultivait establishes an uncompromised privacy and consent architecture for the design-partner cohort: data sharing is strictly **pull-only** via `kultivait report --export`, writing a scrubbed local artifact that the human operator inspects and transmits themselves, while **no network transmit code path exists anywhere in the product**, ensuring the foundational "Nothing-phones-home" claim remains literally true by construction. Route outcome records extend the primary ledger with `policy_version`, `repo_hash`, and `outcome_label` (`accepted`, `retried`, `escalated`, `wrong_route`) and record metadata only (candidate tiers, confidence, override, retry, fallback, latency, cloud-egress decision; zero prompt text or model completions) with repository identity scrubbed to a **salted per-install repo hash** (`repo_hash`) rather than filesystem paths or repository names. Snippet retention operates on a strict **per-repo opt-in** basis governed by test-enforced **secret-shape refusal** (text matching secret or credential token patterns is refused and never stored under any circumstance, with the redaction event itself logged as an invariant), and snippets never leave the host machine unless an export is explicitly generated with `--include-snippets`. The default cloud-egress posture for any newly encountered repository is **ask-once-per-repo** (the first prospective frontier dispatch pauses once, tollbooth-style, recording the operator's consent in local policy), while opted-out repositories enforce an unconditional, **test-enforced block** that guarantees zero cloud egress. This posture keeps the launch-checklist zero-telemetry axis unconditionally green, ensures that consent remains an explicit human action outside the product, bounds project-side retention to deletion 90 days after the expansion memo publishes (and within 14 days upon partner exit request), and enables empirical evaluation of routing safety against a pre-registered route regret ceiling (≤10%, measured as wrong-route labels divided by all labeled dispatches).

## Considered Options

- **Opt-in push telemetry (daemon background beacon / HTTP upload endpoint)**: rejected — writes telemetry code into a product whose primary market distinction and competitive posture is the complete absence of telemetry; would require carving exceptions into the launch checklist's zero-telemetry axis and compromising the verifiable "0 bytes phoned home" guarantee.
- **Raw repo paths in metadata**: rejected — recording local directory names or filesystem paths leaks private organization structures, client identities, and directory hierarchies into shared artifacts; salted per-install hashes preserve per-repo analytical grouping while guaranteeing zero structural leakage.
- **Global-only snippet opt-in (machine-wide toggle)**: rejected — too coarse for developers who alternate between public open-source development and sensitive proprietary codebases; per-repo opt-in provides necessary sovereign control.
- **Block-default cloud-egress posture**: rejected — quietly breaks the selective escalation and frontier fallback value proposition that makes kultivait valuable for complex agentic workflows; users perceive silent failures rather than informed choices.
- **Allow-default cloud-egress posture**: rejected — contradicts the core explicit-and-inspectable privacy invariant, risking accidental transmission of private repository context to cloud models before the operator has established policy.

## Consequences

- The launch-checklist no-telemetry axis stays trivially green by construction with zero exceptions, waivers, or telemetry libraries in the dependency graph.
- Consent is maintained as an explicit human act conducted outside the product boundaries rather than automated software consent.
- The §A.5 zero-egress guarantee for opted-out repositories is enforced by product-behavior unit and integration tests, not documentation prose.
- Exports are scrubbed locally on generation, with project-side retention strictly bounded to deletion 90 days after the expansion memo publishes (and partner export deletion fulfilled within 14 days on request).
- Terms canonized in CONTEXT.md: **Route outcome record**, **Pull-only export**, **Route regret**, and **Secret-shape refusal**.
