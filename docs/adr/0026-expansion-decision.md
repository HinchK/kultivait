# The 180-day expansion decision: double down on the individual developer product

Following the completion of Map #221 and the evaluation of empirical evidence across the Phase 1 design-partner cohort (ADR 0025, #222), kultivait evaluates three strategic candidate trajectories for the 91–180 day roadmap horizon—Path 1: Stronger individual developer product; Path 2: Self-hosted team mode; and Path 3: Deeper runtime expansion around llama.cpp—and formally selects **Path 1 (Stronger individual developer product)** as the exclusive focus of Phase 2 engineering. Phase 1 evidence demonstrably revealed that user pull centers entirely on local sovereignty, immediate workflow integration, and friction-free agent loops: developers adopt kultivait when it invisibly speeds up and cuts costs on their private Apple Silicon machines, while team-mode features (central proxies, shared billing, RBAC, aggregate analytics) showed zero user demand and would encumber the project with enterprise bloat, multi-tenant attack surfaces, and centralized infrastructure requirements directly counter to the local-first philosophy. Simultaneously, Phase 1 runtime data confirmed that Ollama delivers the necessary reliability, process daemon maturity, and zero-config bootstrap required for mainstream stability, whereas elevating llama.cpp to a co-equal default (Path 3) introduces severe maintenance drag, dual-runtime test matrix inflation, and brittle router-mode process supervision for marginal latency advantages. By doubling down exclusively on the standalone developer experience, Phase 2 commits to strict, pre-registered quantitative success bars: (1) **Packaging & Installation Friction**: a one-line installer reducing cold onboarding friction to under 60 seconds; (2) **Agent Auto-Integration**: zero-config environment injection and configuration patching across supported agent harnesses (Claude Code, Pi, OpenCode, Cursor, Aider); (3) **Sub-Millisecond Route Explanation**: transparent in-band routing diagnostic metadata (`route explanation`) with less than 1.0 ms wall-clock overhead; (4) **Curated Local Gardens**: hardware-tuned model bundles guaranteeing a 100% pass rate on OpenAI and Anthropic tool-calling contracts across supported quantization tiers; and (5) **Zero-Telemetry Invariant**: unwavering preservation of the pull-only data-sharing posture established in ADR 0025, maintaining zero background network transmit code paths.

## Considered Options

- **Path 2: Self-hosted team mode (centralized gateway proxy, shared organization billing, RBAC, team dashboards)**: rejected — zero user pull from design partners whose core motivation is local data confidentiality; introduces substantial architectural complexity (user authentication, secret stores, network tenancy isolation, multi-user concurrency locks) and diverts focus from the desktop developer loop into enterprise SaaS plumbing.
- **Path 3: Deeper runtime expansion / llama.cpp as co-equal default**: rejected — maintaining two divergent local serving backends with distinct context-window semantics, tool-call dialects, and process supervisor requirements doubles the test matrix and operational surface area without improving the developer's core routing experience; Ollama remains the battle-tested, zero-maintenance default engine.
- **Split-focus roadmap (parallel execution of Path 1 and Path 2 or 3)**: rejected — fractures herd engineering bandwidth across competing paradigms; solitary focus on individual developer mastery yields the highest product quality, cleanest architecture, and fastest velocity.

## Consequences

- All engineering, roadmap priorities, and evaluation gates for Days 91–180 are allocated exclusively to Path 1 (individual developer experience).
- The default serving engine remains permanently pinned to Ollama (`runtime = "ollama"`); llama.cpp remains an optional, experimental community route with zero release-blocking obligations.
- Team-oriented functionality (central proxies, RBAC, organization user accounts, remote telemetry aggregators) is declared an explicit non-goal and parked indefinitely.
- Phase 2 establishes pre-registered acceptance gates: one-line installer friction under 60 seconds, automated agent harness hooks, sub-1ms routing explanation latency, 100% tool-contract pass on curated gardens, and absolute maintenance of the zero-telemetry posture.
- Terms canonized in CONTEXT.md: **Curated local garden**, **Route explanation**, **Agent auto-integration**, and **Expansion path**.
