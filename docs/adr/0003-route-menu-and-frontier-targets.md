# Route menu presents ranked installed targets with auto-policy local default

When a routing verdict is contested and a trolltoll holds the request (docs/adr/0001-trolltoll-holds-requests.md), the tollbooth presents a route menu offering the top three registered, installed frontier CLI targets ranked by a deterministic total order — judge fit descending (decision #7 raw material) → task_type capability match → price ascending — anchored by a fourth keep-it-local option, rather than dynamically fitting arbitrary models or querying uninstalled candidates. We chose this fixed ranking and installed-only constraint because CLI tiers represent concrete local binary installations and configured models (src/kultivait/config.py:26-31, :84-143), where fitted effort (decision #13's `resolve_effort()`) is projected directly onto per-CLI adapters, per-target prompt rewrites accompany frontier options, and keep-it-local dispatches through established tier resolution (src/kultivait/server.py:119-150) while archiving escalation-style (`route_choice: "local"`) to preserve training signals without corrupting silent-downgrade tracking (`fallback_reason`). If the trolltoll expires without a human response, auto-policy enforces kultivait's reduce-first ethos: it dispatches to the local tier whenever serving-capable, and only routes to the top-ranked frontier target when local execution cannot serve the request (`no_backend` or `tools_unsupported` per src/kultivait/server.py:130-134), archiving the full offered route menu and recording expired counterfactuals in the ledger (docs/adr/0001-trolltoll-holds-requests.md, docs/adr/0002-orchestration-fit-at-boundaries.md).

## Considered Options

- **Dynamic model fitting per option with uninstalled target synthesis**: rejected because CLI tiers represent concrete binaries on the user's host; offering uninstalled targets creates broken execution paths and inflating options beyond installed tools violates simplicity. Kept parts: all registered installed CLIs qualify as route menu candidates regardless of which CLI occupied the single architect or docs role slot in `detect()`.
- **Headless auto-policy always dispatching the top frontier target**: rejected because defaulting to costly cloud dispatches on unanswered requests violates kultivait's core ethos (reduce → right-size → localize) and penalizes unattended runs. Kept parts: auto-policy routes to the top-ranked frontier target strictly when the local backend is unavailable (`no_backend`) or incapable of handling request tools (`tools_unsupported`).
- **Treating deliberate local selection as a silent downgrade**: rejected because human choice on a contested prompt is an intentional routing decision rather than an unexpected system limitation (`fallback_reason`). Kept parts: human local choices archive full context escalation-style with `route_choice: "local"` for later distillation, keeping the `fallback_reason` telemetry field pure.

## Consequences

- Route menu construction deterministically orders up to three installed frontier targets using judge fits descending, task_type capability alignment, and token pricing ascending (src/kultivait/config.py:26-31), always including keep-it-local with the original unrewritten prompt.
- Each frontier option carries its per-target prompt rewrite (decision #7) and canonical effort projected onto target CLI mechanisms (claude/agy `--effort`, codex `-c model_reasoning_effort`, opencode `run --variant`, gemini `thinkingLevel`/`thinkingBudget`), with interactive re-fit supported on tollbooth override (decision #13).
- Deliberate local choices dispatch via `_resolve_tier` (src/kultivait/server.py:119-150) and archive escalation-style under `route_choice: "local"`, distinguishing human local choices from infrastructure fallbacks (`fallback_reason`).
- Auto-policy on expired trolltolls dispatches locally when serving-capable, routing to the top frontier target only on `no_backend` or `tools_unsupported`, while archiving the complete offered route menu and recording `route_choice: "auto:local"` or `"auto:frontier:<target>"` with `toll: "expired"` in the ledger.
- `KNOWN_CLIS` and `CLI_PRICING` register `codex` (`architect`, $1.25/$10.00) and `opencode` (`architect`, $3.00/$15.00 baseline with multi-provider caveat), unblocking architect-slot resolution on machines lacking `claude` and establishing future dispatch templates (`codex exec <prompt>`, `opencode run <prompt>`) without altering config data structures.
