# API effort projection: canonical currency, backends self-project, per-model token tables, sticky per (fingerprint, target)

Canonical effort (fast/balanced/deep, resolved by `resolve_effort` from complexity × task_type with the no-signal default balanced, docs/adr/0003) remains the **only shared currency**; `effort.py`'s CLI projection table is unchanged, and each API backend **projects canonical onto its own wire fields itself** — no api branches join the adapter table, no `api_params` ride `EffortPlan` (whose fallthrough branch already yields canonical-only plans for non-CLI targets). The projection tables are deliberately **per-provider divergent**, owned by the backend that knows its provider: OpenAI `reasoning_effort` projects fast→low, balanced→medium, **deep→xhigh** (gpt-5.6-family subset); Anthropic `output_config.effort` projects fast→low, balanced→medium, **deep→high** (xhigh reserved, never auto-projected); OpenRouter emits the OpenAI-normalized `reasoning_effort` mirroring the OpenAI table (the `:thinking` model suffix is rejected — it fights pinned model ids; manual `thinking.budget_tokens` is dead — 400 on Claude 4.7+/5-series — and is never emitted). Token safety runs off a **fixed per-model table** carried alongside the curated pricing defaults (docs/adr/0004): each pinned model records its default max output tokens and the correct field name (`max_completion_tokens` on OpenAI reasoning models, where plain `max_tokens` is deprecated/incompatible; `max_tokens` on Anthropic, where it is required). A client-present max_tokens passes through and is **never lowered**; when absent the per-model default applies; the backend raises the default when the projected effort demands headroom (never truncate below what the effort needs — OpenAI recommends ≥25k output headroom for deep reasoning). Effort is **sticky per (conversation fingerprint, target) pair**, extending the tollbooth's fingerprint-stickiness cache: the first resolution per pair wins, auto re-fits at boundaries reuse the pair's effort, a target change re-derives (new pair), and a human toll override writes through and sticks for the pair — protecting provider prompt-cache prefixes, which effort changes invalidate on both providers.

## Considered Options

- **`api_params` on EffortPlan** (one adapter table stays the single projection source): rejected — provider knowledge (wire field, value subset, token field) is owned where it is used; a shared table re-centralizes what each backend knows best. Kept parts: canonical resolution and the no-signal balanced default stay centralized in `resolve_effort`.
- **Uniform low/medium/high across providers**: rejected — the providers' scales are not actually uniform (xhigh exists on the OpenAI gpt-5.6 subset; Anthropic reserves it), and per-provider tuning is exactly what backend ownership buys.
- **Effort-tiered token floors** (fast ≈8k / balanced ≈16k / deep ≈32k injected when the client omits max_tokens): rejected as the primary mechanism — the curated per-model table is more honest (per-model real defaults + field names) and already ships with #27's pricing table. Kept parts: the never-truncate-below-effort's-need safety invariant survives as a clamp on the table value.
- **Never set token limits**: rejected outright — Anthropic requires `max_tokens`; deep-effort outputs risk truncation.
- **Fingerprint-wide effort stickiness** (first effort wins for the whole conversation regardless of target): rejected — a target change mid-conversation is a new provider with a new cache and a new scale; the pair (fingerprint, target) is the correct stickiness key.

## Consequences

- `effort.py` needs no change for API targets (the existing fallthrough returns canonical-only plans); each ApiBackend carries its projection table and consults the per-model token table for its pinned model.
- The tollbooth's stickiness cache widens from fingerprint→route to (fingerprint, target)→effort; `RouteOption.effort` continues to hold the canonical plan, and wire projection happens at dispatch inside the backend.
- The ledger stays canonical-only (`canonical_effort` recorded; the wire value is backend-internal and derivable); `cli_effort_flags` stays empty on api dispatches.
- Term canonized in CONTEXT.md: **Effort projection**.
