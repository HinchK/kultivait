# Distillate deployment & shadow rollout: [distill] config seat, post-response shadow on contested traffic, 90/30 human cutover, tagged ledger + shadow log

A distilled model enters serving as **just another local Ollama model** — Modelfile → `ollama create kv-judge-<base>-g<gen>` (ADR 0014's naming); `detect()` never special-cases it, and a distillate is never a routing-candidate tier. The live preprocessor seat lives in a **`[distill]` config section**: `model` (the live preprocess model; the incumbent `qwen3.5:4b` default stands until a cutover writes the knob), plus `shadow_model` and `shadow_mode = "off|on"` — and because the serving generate function resolves the model per-call, a config edit swaps models with **no server restart**; `init`/setup are untouched (the future train/distill command surface writes the section). Shadow comparison rides **only the contested path** (where the incumbent preprocessor already ran — the judgment behavior under test), as a **fire-and-forget background task issued after the live response completes**: same prompt, shadow model, zero latency overhead by construction, 100% sampled at first (contested traffic is scarce — the band is the test) with a sample-rate knob; fat-margin traffic never shadows (serving skips preprocessing there; nothing to compare); shadow runs only when a gate-passing candidate exists (ADR 0015's winners only). **Cutover is a two-condition AND evaluated on the shadow log, flipped by the human** (never automatic): shadow verdict agreement with the incumbent ≥ 90% over ≥ 30 shadowed contested requests (live-distribution sanity — quality was proven offline), AND zero gate-failing anomalies (parse failures < 10%, no dangerous local verdicts on escalatory prompts). **Rollback is instant by construction**: revert the `model` knob and the next request serves the incumbent — no artifacts, no re-registration; post-cutover the incumbent keeps shadowing from below for one week before shadow turns off. Recording is two-layer: the **main ledger tags every preprocessed entry with `preprocess_model`** (always — incumbent or distillate; legacy entries imply `qwen3.5:4b`), so seasons slice by generation; a **separate `~/.kultivait/shadow.jsonl` log** holds per-case `{incumbent, shadow}` verdict/fit/latency/parse pairs — outside the main ledger by design, so shadow outcomes never pollute toll stats, routing analytics, or the harvest's cost lenses — with a `kultivait shadow` read command summarizing agreement, anomalies, and cutover-readiness. The provenance chain is complete: eval records → shadow log → the ledger's `preprocess_model` — every generation's journey is auditable.

## Considered Options

- **Register the distillate as a serving tier** (point preprocessing at a tier name): rejected — conflates the capability-order/routing-candidate tier system with the preprocessor seat; a distillate must never be a routing candidate.
- **Free-form config keys** (no dedicated section): rejected — live and shadow state lack a declared home; future pipeline tooling would guess.
- **Synchronous in-request shadow** (both models before responding): rejected — doubles contested-path latency, breaking the very budget the distillate must preserve.
- **All-traffic shadow** (shadow where serving skips preprocessing): rejected — invents work serving never does; the comparison stops testing the real path.
- **Offline gates only** (no live shadow): rejected — the held-out set is small and static; live-distribution drift stays invisible until after cutover.
- **Automatic cutover** on shadow metrics: rejected — an unattended model swap on the routing brain at n≈30 is weak evidence for autonomy; the human flip is one deliberate edit.
- **Offline-only cutover** (skip shadow criteria): rejected — same drift blindness, one layer earlier.
- **Canary percentage rollout**: rejected — the preprocessor is a single seat; splitting it creates two live verdict sources routing real traffic, complexity without multi-tenant benefit.
- **Shadow outcomes in the main ledger**: rejected — contaminates toll-rate/agreement analytics and double-counts preprocessing marks in the harvest.
- **Counters-only telemetry**: rejected — cutover criteria need per-case agreement; debugging a bad cutover needs the cases.

## Consequences

- `config.py` gains the `[distill]` section (model, shadow_model, shadow_mode, shadow_sample_rate) with round-trip save/load; the server's default generate function reads the seat per-call (restart-free swap; the hardcoded `qwen3.5:4b` fallback becomes the section's default).
- The server's contested path grows an after-response background hook (fire-and-forget, exception-isolated — a shadow crash never touches serving); the shadow log writes are append-only JSONL in the established store pattern.
- The ledger gains `preprocess_model` on preprocessed entries (additive; legacy implies the incumbent); the harvest may slice seasons by generation later without schema change.
- `kultivait shadow` joins the CLI read surface (summary + cutover-readiness); `kultivait train/distill` remains the pipeline build effort's surface, unwritten here.
- Term canonized in CONTEXT.md: **Shadow pass**.
