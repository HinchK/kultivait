# Orchestration fits at boundaries

Kultivait leaves the client's agent loop intact and fits model tier and effort only at request and sub-task boundaries as requests cross the proxy, rather than acting as an autonomous orchestrator that spawns and drives frontier CLIs as workers (HANDOFF.md:191-193's "delegated dispatch" candidate). We chose this because kultivait is a routing layer, not an orchestrator process; driving agent worker processes directly entangles proxy state with external lifecycles and violates runtime boundaries. To handle compound and tool-bearing prompts without introducing a separate, latency-heavy planning-model pass that would bust the request-path budget (p50 ≤ 8s, cap 15s, `preprocess_timeout`), the local preprocessor's single-call analyze pass (decisions #7 and #8) is extended to emit sub-task candidates returned in-band as structured metadata (`kultivait_meta`), adhering to HANDOFF.md:107-113 and ADR 0001's precedent that in-band structured metadata preserves agent loops where prose advice derails them.

## Considered Options

- **Autonomous dispatch orchestrator** (spawning and driving frontier CLIs as background workers; HANDOFF.md's "delegated dispatch" candidate): rejected as the core mechanism because kultivait must remain a routing proxy rather than an execution engine or agent harness; managing autonomous CLI worker loops inside the proxy bloats runtime state and breaks external client control. Kept parts: none for dispatch, but the ledger fields (`orchestrator`, `worker`) from TODO-AGY.md's sketch survive to attribute costs and choices across multi-agent workflows.
- **Dedicated planning-model pass emitting prose advice** (separate orchestrator LLM call before execution): rejected because an additional sequential LLM call busts the request-path latency budget (p50 ≤ 8s, cap 15s), and natural-language advice derails agent loops expecting tool calls or direct content (HANDOFF.md:107-113). Kept parts: folded into the preprocessor — for tool-bearing or compound prompts, the single-call analyze pass emits sub-task candidates in-band as structured metadata (`kultivait_meta`), never as prose advice.
- **Fit model and effort at boundaries with client loop intact**: accepted as the spine — the client's agent loop drives execution, while kultivait fits model selection and effort at each request boundary as requests cross the proxy.

## Consequences

- Tool-bearing requests no longer skip preprocessing entirely; compound and tool-bearing prompts emit sub-task candidates within structured response metadata (`kultivait_meta`) during the existing single-call preprocessor pass, respecting the single latency budget (p50 ≤ 8s, cap 15s, `preprocess_timeout`).
- Mid-flight re-fit requires no secondary holding mechanism: each subsequent request in a conversation fingerprint re-enters the proxy pipeline (fresh embedding margin check → preprocessor fits → derived verdict → effort re-fit), triggering a trolltoll only when the new verdict is contested, bounded by conversation fingerprint stickiness.
- Context fluctuation across sub-task boundaries is managed via per-sub-task briefs generated by the `gates.py` distill-and-compost machinery (keyed by conversation fingerprint within a TTL), supplying frontier targets with distilled briefs via per-target rewrites rather than unpruned transcript drift.
- The hybrid stack sketched in `TODO-AGY.md` (e.g., Claude planning, AGY coding, Qwen editing) is re-cast as a client pattern operating over the proxy; kultivait right-sizes, prices, and ledgers each dispatch rather than managing the agent fleet internally.
- Unblocks map #4's ledger and harvest schema item by establishing that ledger records will capture `orchestrator` and `worker` metadata fields alongside routing verdicts and effort parameters (formal schema definition deferred to a separate ticket).
