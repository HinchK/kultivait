# API frontier: three standalone provider backends, manual registration, pinned model ids

The REST frontier (map #25) enters kultivait as three providers — Anthropic direct, OpenAI direct, and OpenRouter — built in that reverse order of dependency (OpenRouter first as the thin wedge: one key, both client dialects natively, per-response USD `usage.cost`; then Anthropic direct for first-party fidelity and cache-aware ITPM; then OpenAI direct), served by **three standalone backend classes** (`OpenAIBackend`, `AnthropicBackend`, `OpenRouterBackend` in src/kultivait/backends.py, httpx — already a dependency) rather than one dialect-parameterized class: the two wire grammars differ in terminator, usage cadence, keep-alives, and tool-argument fragment keys (experiments/rest-capability-matrix.md §b), so each class owns a per-dialect SSE event normalizer while sharing translation tables and parsing as module-level pure helpers, never inheritance. All three conform to the existing `Backend` protocol (complete/stream with tools + effort_flags + model_override, yielding `Completion` with `tool_calls`), declare `supports_tools = True` and `local = False`, and thereby dissolve the `tools_unsupported` gate (src/kultivait/server.py `_resolve_tier`) for client tool agents while keeping the client's agent loop the orchestrator (docs/adr/0002-orchestration-fit-at-boundaries.md). Registration is **manual**: a `[[tiers]]` block with `kind = "api"`, hand-edited — `detect()` (src/kultivait/config.py) is deliberately untouched; **registered** means the tier exists in the TOML, **served** means its key resolves at backend construction, and an unresolvable key excludes the target from route-menu candidacy exactly as a missing CLI binary excludes a CLI target. Model ids are **pinned exact** (per-token prices, cache multipliers, and effort value subsets all key on the exact id — experiments/rest-capability-matrix.md §e–f); a curated defaults table (sonnet-5-class, terra-class, and OpenRouter equivalents with prices) ships as the copy-ready source, and an api tier lacking prices loads a conservative frontier default with a warning so ledger math never silently reads $0.

## Considered Options

- **One `ApiBackend` class with a `dialect` parameter** (OpenRouter = openai-dialect + base_url/auth/cost overrides): rejected for spec clarity — three named classes read at a glance in config and ledger traces, and the OpenAI/OpenRouter overlap lives in shared pure helpers instead of a parameter switch. The duplication cost is one thin class shell.
- **`KNOWN_PROVIDERS` registry with `detect()` auto-registration** (key-present ⇒ auto-registered, mirroring KNOWN_CLIS): rejected because provider tiers carry hand-chosen model pins and prices that auto-detection cannot infer; registration is a deliberate act, not an ambient machine fact. Kept parts: the curated defaults table exists for copying, and key resolvability still gates serving.
- **Floating/versionless model aliases**: rejected because pricing tables, cache multipliers, and per-model effort subsets key on exact ids; a floating alias silently breaks cost accounting (decision feeds #28) and effort projection (#31).
- **OpenRouter-only v1**: rejected as the permanent shape (retained as the first build phase) — it forgoes Anthropic cache-read ITPM exemption for tool-heavy loops and first-party rate-limit headers.

## Consequences

- Build phasing for the eventual /to-tickets effort: OpenRouter wedge (OpenAI-dialect core + both client dialects + USD cost ground truth) → Anthropic direct (flat tool schema, `x-api-key` + `anthropic-version`, `output_config.effort`) → OpenAI direct (`reasoning_effort`, opt-in usage chunk).
- The route menu (docs/adr/0003-route-menu-and-frontier-targets.md) gains api-kind tiers as frontier candidates alongside installed CLIs; the "installed" predicate for them is tier-present + key-resolvable, checked at backend construction.
- Effort projection collapses to one ordinal mechanism per provider (fast/balanced/deep → low/medium/high[-xhigh]); the adapter shape is decision #31's, extending `resolve_effort()` beyond the four CLI mechanisms.
- Cost accounting stays asymmetric (OpenRouter reports USD; Anthropic/OpenAI report tokens needing the price table, including Anthropic's three-way input split) — the duality is decision #28's to resolve.
- `TierSpec.kind` gains `"api"`; `save_config`/`load_config` round-trip it unchanged; no other config surface moves.
- Terms canonized in CONTEXT.md: **Frontier provider**, **Dialect**.
